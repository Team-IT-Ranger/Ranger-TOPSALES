# ตรวจโครง DBF ของ Express ก่อนเขียนไฟล์จริง

`Get-DbfSchema.ps1` — **อ่านอย่างเดียว ไม่เขียนอะไรลงไฟล์ `.dbf` เลย** เอาไปรันบนเครื่องของตัวแทนได้
โดยไม่ต้องปิด Express และไม่ต้องติดตั้งอะไรเพิ่ม (PowerShell มากับ Windows อยู่แล้ว)

## ทำไมต้องตรวจก่อน

โครง DBF ของ Express **คนละเวอร์ชันไม่เหมือนกัน** และถ้าเราเขียนไฟล์ตามโครงที่ผิดแม้ไบต์เดียว
**ตารางพังทั้งตาราง ไม่ใช่แค่แถวเดียว** — ทดสอบแล้วด้วยการแก้ `ARMAS.CUSCOD` จาก `C(10)` เป็น `C(12)`
ฟิลด์ที่เหลืออีก 38 ตัวขยับตำแหน่งตามกันทั้งแถว ทุกค่าหลังจากนั้นจะถูกเขียนลงผิดช่วงไบต์

## ขั้นตอน

```powershell
# บนเครื่องของตัวแทน — ดูโครงเฉยๆ
.\Get-DbfSchema.ps1 -Path 'C:\ExpressI\<โฟลเดอร์ข้อมูล>'

# เทียบกับแบบที่เราเก็บไว้ (ไฟล์ schema-baseline.json ส่งไปพร้อมกัน)
.\Get-DbfSchema.ps1 -Path 'C:\ExpressI\<โฟลเดอร์ข้อมูล>' -Baseline '.\schema-baseline.json'

# เก็บผลเป็นไฟล์ส่งกลับมาให้เราดู
.\Get-DbfSchema.ps1 -Path 'C:\ExpressI\<โฟลเดอร์ข้อมูล>' -SaveBaseline '.\schema-ตัวแทน.json'
```

รหัสจบการทำงาน: `0` = โครงตรงกันทุกตาราง · `1` = มีจุดต่าง (ห้ามใช้โครงเดิมเขียนไฟล์) · `2` = เปิดไฟล์ไม่ได้

## ข้อควรรู้

- **ไฟล์ `.ps1` ต้องมี BOM** — Windows PowerShell 5.1 อ่านไฟล์ที่ไม่มี BOM เป็น ANSI
  ภาษาไทยในสคริปต์จะเพี้ยนจนสคริปต์ไม่ทำงาน (เจอมาแล้ว) · คัดลอกไฟล์ไปแบบไบนารีเสมอ
  อย่าเปิดแก้แล้วเซฟด้วย Notepad แบบ UTF-8 ธรรมดา
- เปิดไฟล์ด้วย `FileShare::ReadWrite` จึงอ่านได้แม้ Express กำลังเปิดไฟล์นั้นค้างอยู่
- ถ้าเครื่องห้ามรันสคริปต์: `powershell -NoProfile -ExecutionPolicy Bypass -File .\Get-DbfSchema.ps1 ...`

## ★ ไบต์ "วันที่แก้ล่าสุด" ของ Express ไม่ตรงมาตรฐาน DBF

มาตรฐานคือ **ปี ค.ศ. − 1900** (ปี 2026 ต้องได้ 126) แต่ไฟล์ที่ Express เขียนเองได้ **234** ทุกไฟล์
(ตรวจ 15 ต.ค. 2026: ARTRN · ARBAL · ARMAS · GLJNL · GLJNLIT · ISRUN · ISVAT · STCRD · STLOC · STMAS
จากเครื่องตัวแทน ได้ 234 เหมือนกันหมด ส่วนไฟล์ที่ **เราสร้างเอง** ด้วยไลบรารี Python ได้ 126 ตามมาตรฐาน)

ผลสองข้อ:
1. **อย่าเชื่อวันที่ในหัวตาราง** และตอนเขียนไฟล์จริง **ต้องลอกค่าที่ Express ใช้ ไม่ใช่คิดเอง**
2. ไบต์นี้ใช้แยกได้ว่าไฟล์ไหน Express เขียน ไฟล์ไหนเราเขียน — สคริปต์เตือนให้เองเมื่อเจอค่า 126

## สิ่งที่เก็บไว้แล้ว (`schema-baseline.json`)

เก็บจากไฟล์ของ **ตัวแทน** (ชุดที่ส่งมา 15 ต.ค. 2026) ครบ 10 ตาราง — **ไม่ได้ใช้ไฟล์จากไดรฟ์ `Z:`
ของเครื่องนี้** เพราะเป็น Express คนละเวอร์ชันกับของตัวแทน (เจ้าของระบบสั่ง 24 ต.ค. 2026)

| ตาราง | แถว | ยาวแถว (ไบต์) |
|---|---|---|
| ARMAS (ทะเบียนลูกหนี้) | 2,040 | 622 |
| ARBAL (ยอดลูกหนี้) | 2,040 | 979 |
| ARTRN (รายการลูกหนี้) | 29 | 427 |
| GLJNL / GLJNLIT (สมุดรายวัน) | 34 / 102 | 185 / 148 |
| ISRUN (เลขที่เอกสาร) | 117 | 365 |
| ISVAT (ภาษี) | 31 | 238 |
| STCRD (การ์ดสินค้า) | 96 | 417 |
| STLOC (สินค้าตามคลัง) | 31 | 555 |
| STMAS (ทะเบียนสินค้า) | 28 | 643 |

ทั้ง 10 ตารางเป็น Visual FoxPro (0x30) · รหัสหน้า **0x7C = 874 (ไทย Windows)** · ผ่านการตรวจความสมบูรณ์
ทุกข้อ (ผลรวมความยาวฟิลด์ = ความยาวแถว · ขนาดไฟล์ตรงกับที่หัวตารางบอก · ไม่มีชนิดฟิลด์แปลกปลอม)

## ★★ ยังขาด OESO / OESOIT

**สองตารางที่เราต้องเขียนจริง — ใบสั่งขาย (`OESO`) และรายการในใบ (`OESOIT`) — ไม่ได้อยู่ในชุดที่ตัวแทนส่งมา**
ที่บันทึกไว้ใน `docs/express-interface-notes.md` เป็นโครงจากเครื่องนี้ (Express ปี 2013) ซึ่งใช้ยึดไม่ได้

**ต้องขอสองไฟล์นี้จากเครื่องของตัวแทนก่อน** ถึงจะเริ่มเขียนตัวสร้างไฟล์ได้ — หรือให้เขารัน
สคริปต์นี้บนเครื่องตัวเองแล้วส่ง JSON กลับมา (ไม่ต้องส่งไฟล์ข้อมูลจริงออกจากเครื่องเขาเลย
ซึ่งปลอดภัยกว่าสำหรับข้อมูลลูกค้าของเขาด้วย)

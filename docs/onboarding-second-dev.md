## 1. Clone

```bash
git clone https://github.com/Team-IT-Ranger/Ranger-TOPSALES.git
cd Ranger-TOPSALES
git checkout UAT
```

**★ ต้อง clone ลงดิสก์ในเครื่อง (`C:\...`) ห้ามลง `G:\Shared drives\...`**
ไดรฟ์ไม่ merge ไฟล์ที่เขียนพร้อมกัน มันสร้างไฟล์คู่ขนานแทน แล้ว `.git` เสียทั้งก้อน — เหตุผลเต็มอยู่ใน CLAUDE.md
ที่นั่นเคยเสียมาแล้วจริง · โฟลเดอร์บนไดรฟ์เหลือบทบาทเป็นที่เก็บ `reference/` อย่างเดียว

**เครื่องมือที่ต้องมี**: `git` · `node` (เครื่องแรกใช้ v25) · `python` (ไว้รันเซิร์ฟเวอร์พรีวิว)
· `clasp` (v3, เฉพาะคนที่ทำ backend) → `npm i -g @google/clasp` แล้ว `clasp login`
ด้วยบัญชีที่มีสิทธิ์ **Editor** บนโปรเจกต์ Apps Script ของ UAT · login นี้เป็นของแต่ละเครื่อง

## 2. ของที่ clone ใหม่จะไม่มี (gitignored)

ไม่ใช่ของหาย — ตั้งใจไม่ขึ้น GitHub · รู้ไว้ก่อนจะได้ไม่งงว่าทำไมบางอย่างพัง

| ไฟล์ | ผลถ้าไม่มี | ทำยังไง |
|---|---|---|
| `.dev/xlsx.full.min.js` | `test-pricelist-parser.js` และสคริปต์ `import-*.js` ทั้ง 3 ตัวรันไม่ได้ | โหลด SheetJS จาก CDN มาวาง หรือก๊อปจากเครื่องแรก · ไม่ได้ทำเรื่องนำเข้าไฟล์ก็ข้ามได้ |
| `reference/` | ไม่มีใบราคา/แฟ้มลูกค้าจริง | อ่านจาก `G:\Shared drives\AppSpace\Ranger-TOPSALES\reference\` ตรงๆ |
| `backend/script_properties.gs` | — | **ไม่ต้องใช้** ค่าจริงอยู่ใน Script Properties ฝั่ง Google แล้ว (ดู CLAUDE.md) |
| `.claude/settings.local.json` | Claude จะขออนุญาตบ่อยช่วงแรก | ปกติ อนุญาตไปตามที่ใช้ |

`.claude/launch.json` **มีในรีโป** — เซิร์ฟเวอร์พรีวิวจึงใช้ได้เลยไม่ต้องตั้งอะไร

## 3. ตรวจว่าเครื่องพร้อม

```bash
for f in .dev/test-*.js; do printf '%-34s' "$(basename $f)"; node "$f" >/dev/null 2>&1 && echo OK || echo FAIL; done
```

ต้อง **OK ทั้งหมด ยกเว้น `test-pricelist-parser.js`** ที่ FAIL เพราะไฟล์ SheetJS ในข้อ 2
· เทสต์ชุดนี้ไม่ยิงเน็ตเลย รันที่ไหนก็ได้ · ถ้ามีตัวอื่น FAIL แปลว่าเครื่องยังไม่พร้อม อย่าเพิ่งเริ่มงาน

อยากดูหน้าเว็บ: เปิดเซิร์ฟเวอร์พรีวิว `frontend-admin` (ผ่าน `.claude/launch.json`) แล้วเข้า `localhost:5500`

> **★ พรีวิวในเครื่องไม่ใช่กระบะทราย** — `config.js` ตัดสินว่า `localhost` = env `uat`
> หน้าเว็บที่รันในเครื่องจึงยิงเข้า **backend UAT ตัวจริงและข้อมูลจริงที่อีกคนใช้อยู่**
> กดปุ่มที่บันทึกข้อมูลได้ = เขียนของจริง ระวังเรื่องที่แก้เป็นชุด (ดูกุญแจใน `who-is-doing-what.md`)

## 4. ข้อความแรกที่ส่งให้ Claude ของคนที่สอง

Claude อ่าน `CLAUDE.md` เองตอนเปิด session อยู่แล้ว **ไม่ต้องอธิบายกติกาซ้ำ** ส่งแค่นี้พอ:

```
เราพัฒนาแอปนี้กัน 2 คน — อ่าน CLAUDE.md หัวข้อ "ทำงานสองคน" และ docs/who-is-doing-what.md ก่อนลงมือ

เลนของคุณ: backend/*.gs + เทสต์ใน .dev/
เลนของอีกคน: frontend-admin/index.html — ห้ามแตะถ้ายังไม่ได้ตกลงกัน

เริ่มจาก:
1. git checkout UAT && git pull
2. รันเทสต์ทั้งชุดดูว่าเครื่องพร้อม (ดู docs/onboarding-second-dev.md ข้อ 3)
3. เขียนบรรทัด "เลน backend" ใน docs/who-is-doing-what.md ว่าจะทำอะไร
4. แตกกิ่ง uat/<ชื่องาน> แล้วเริ่ม — งานที่ว่างอยู่ดูในคิวท้าย who-is-doing-what.md

ก่อน clasp push ขึ้น UAT ต้องจับกุญแจใน who-is-doing-what.md ก่อนทุกครั้ง
UAT มีโปรเจกต์เดียวกับ Central Sheet เดียว push ทับกันได้
```

ขั้นที่ 2 ทำสองอย่างพร้อมกัน: พิสูจน์ว่าเครื่องพร้อม และทำให้ Claude ของเขาเห็นว่าระบบมีโมดูลอะไรบ้าง
โดยไม่ต้องไล่อ่านทั้งรีโป

## 5. สามข้อที่พลาดกันบ่อยที่สุด

1. **ทำงานในโฟลเดอร์ `G:`** — ข้อ 1 · อันนี้พังแบบซ่อมไม่ได้ ต้อง clone ใหม่
2. **`clasp push` โดยไม่บอก** — โปรเจกต์ UAT มีตัวเดียว push ทับกันได้ และอีกคนจะเทสต์โค้ดเราโดยไม่รู้ตัว
3. **commit ตรงเข้า `UAT` โดยไม่ pull ก่อน** — แตกกิ่ง `uat/<เรื่อง>` แล้ว merge กลับเร็วๆ
   ห้ามปล่อยกิ่งค้างข้ามวัน เพราะ `index.html` กับ `CLAUDE.md` เป็นไฟล์ใหญ่ที่ทุกงานไปลง

เหตุผลเบื้องหลังทั้งสามข้อและตัวเลขที่วัดมา อยู่ใน CLAUDE.md หัวข้อ "ทำงานสองคน"

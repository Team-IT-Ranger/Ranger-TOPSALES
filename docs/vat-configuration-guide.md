# แนวทางการตั้งค่าและคิด VAT

สรุปจากระบบที่ใช้งานจริงใน Hippo Village เพื่อให้ **Ranger TOPSHOP** นำไปทำตาม

เรื่อง VAT พังแล้วเจ็บกว่าเรื่องอื่น เพราะผิดแล้วไม่มีอะไรฟ้อง — เอกสารพิมพ์ออกมาสวยงามทุกอย่าง
ผิดแค่ตัวเลข และกว่าจะรู้ก็ตอนบัญชีปิดงบหรือสรรพากรถาม ทุกข้อในนี้มีที่มาจากของที่เคยพังจริง

---

# 1. ค่าตั้งอยู่สามชั้น ต้องรู้ว่าชั้นไหนทำหน้าที่อะไร

```
บริษัท    vat_rate            อัตรา VAT เช่น 7            ← ค่ากลาง เปลี่ยนที่เดียว
          default_vat_type    exclusive | inclusive      ← ค่าตั้งต้นของใบใหม่

ลูกค้า    apply_vat           true | false               ← ลูกค้ารายนี้คิด VAT ไหม

สินค้า    vat_applicable      true | false               ← สินค้าตัวนี้คิด VAT ไหม
```

**ชั้นบริษัท** เป็นค่ากลาง เก็บใน `companies` — ไม่ใช่ค่าคงที่ในโค้ด เพราะอัตราภาษีเปลี่ยนได้
(ไทยเคยลด 10% เหลือ 7% และต่ออายุทุกปี) และระบบรองรับหลายบริษัทที่อาจจดทะเบียนต่างกัน

**ชั้นลูกค้า** บางรายไม่อยู่ในระบบ VAT หรือขายส่งออกอัตราศูนย์

**ชั้นสินค้า** บางรายการได้รับยกเว้น (สินค้าเกษตรที่ยังไม่แปรรูป เป็นต้น)

> ## ⚠️ ข้อเท็จจริงที่ต้องรู้ก่อนลอก
>
> **ใน Hippo Village ชั้นสินค้า (`vat_applicable`) มีช่องให้กรอกและเก็บลงฐานข้อมูลจริง
> แต่ยังไม่เคยถูกนำไปใช้คำนวณเลย** — `_soComputeTotals` คิด VAT กับยอดทั้งใบ ไม่ได้แยกรายบรรทัด
>
> ถ้า TOPSHOP ขายของที่มีทั้งแบบคิดและไม่คิด VAT ปนกันในใบเดียว **ต้องทำส่วนนี้เพิ่มเอง**
> (ดูข้อ 7) อย่าเห็นว่ามีคอลัมน์แล้วคิดว่าระบบทำให้แล้ว

# 2. ★★★ inclusive กับ exclusive คิดคนละสูตร ห้ามสลับ

นี่คือจุดที่พลาดแล้วยอดผิดทันทีและหายากที่สุด

| | ความหมาย | สูตร | ยอดรวมสุดท้าย |
|---|---|---|---|
| **exclusive** | ราคายังไม่รวม VAT | `vat = ฐาน × 0.07` | **เพิ่มขึ้น** |
| **inclusive** | ราคารวม VAT แล้ว | `vat = ฐาน × 0.07 ÷ 1.07` | **เท่าเดิม** |

```js
if (applyVat) {
  if (vatType === 'inclusive') {
    // ราคารวม VAT แล้ว: ถอด VAT ออกมาแสดง ยอดรวมไม่เปลี่ยน
    vatAmount = Math.round((beforeVat * vatRate / (1 + vatRate)) * 100) / 100;
  } else {
    // ราคาไม่รวม VAT: บวก VAT เพิ่มจากยอด
    vatAmount = Math.round((beforeVat * vatRate) * 100) / 100;
    total = beforeVat + vatAmount;
  }
}
```

**ตัวอย่างที่ต้องเข้าใจให้ตรงกัน** — ราคา 107 บาท

- **inclusive** → VAT = 107 × 0.07 ÷ 1.07 = **7.00** · ฐาน 100 · **ลูกค้าจ่าย 107**
- **exclusive** → VAT = 107 × 0.07 = **7.49** · ฐาน 107 · **ลูกค้าจ่าย 114.49**

ต่างกัน 7.49 บาทจากเลขชุดเดียวกัน แค่ตีความคนละแบบ

**เลือกยังไง:** ถามว่า *"ราคาที่พิมพ์อยู่บนป้าย/ในระบบ คือราคาที่ลูกค้าจ่ายจริงหรือยัง"*
ถ้าใช่ = inclusive ถ้ายังต้องบวกเพิ่ม = exclusive

**สำหรับงานรถเร่แบบ TOPSHOP มักเป็น inclusive** เพราะราคาที่แจ้งหน้าร้านคือราคาที่เก็บเงินจริง
พนักงานขายไม่ได้มานั่งบวก 7% หน้าลูกค้า — **แต่ต้องยืนยันกับฝ่ายบัญชีก่อน อย่าเดา**

# 3. อัตรา VAT ต้องเป็นค่าตั้ง ห้ามฮาร์ดโค้ด

```js
// ⚠️ อัตรา VAT ที่หน้าบ้านส่งมาเป็น "เปอร์เซ็นต์" (เช่น 7) แต่เก็บและคำนวณเป็นทศนิยม (0.07)
//    เดิมตรงนี้ฮาร์ดโค้ด 0.07 ทิ้งค่าที่ตั้งไว้ในหน้าตั้งค่าบริษัทไปทั้งหมด
//    ตั้ง VAT เป็น 10% ก็ยังคิดให้ 7% เงียบ ๆ โดยไม่มีอะไรฟ้อง
var vatRate = (parseFloat(vatRateRaw) || 7) / 100;
```

**บั๊กนี้เกิดขึ้นจริง** มีหน้าตั้งค่าให้กรอกอัตรา กรอกแล้วบันทึกสำเร็จ แสดงผลถูก แต่ตอนคำนวณ
ไม่ได้เอาไปใช้ — ระบบที่ "มีหน้าตั้งค่าแต่ไม่ได้ใช้ค่านั้น" อันตรายกว่าไม่มีหน้าตั้งค่าเลย
เพราะคนเชื่อว่าตั้งแล้ว

**★ ระวังหน่วยเปอร์เซ็นต์กับทศนิยมปนกัน** — ตกลงให้ชัดว่าที่ไหนเป็นอะไร แล้วแปลงที่จุดเดียว
ในที่นี้ **หน้าจอและฐานข้อมูลเก็บเป็นเปอร์เซ็นต์ (7) ส่วนการคำนวณใช้ทศนิยม (0.07)**
และแปลงในบรรทัดเดียวข้างบนนั้น ที่อื่นห้ามแปลงซ้ำ

**ป้ายบนหน้าจอต้องอ่านจากค่าจริง** อย่าเขียน `VAT 7%` ตายไว้ใน HTML — ตั้งเป็น 10 แล้วป้าย
ยังบอก 7 คือการโกหกผู้ใช้

# 4. ★★★ บันทึก VAT ลงในเอกสารเป็นภาพนิ่ง ไม่ใช่คำนวณใหม่ตอนเปิดดู

ทุกใบขายเก็บสี่ค่านี้ลงไปในแถวของมันเอง

```js
apply_vat  : 'true' | 'false'      คิด VAT ไหม
vat_type   : 'inclusive' | 'exclusive'
vat_rate   : 0.07                  ← อัตรา ณ วันที่ออกใบ
vat_amount : 350.00                ← จำนวนเงินที่คำนวณได้ ณ ตอนนั้น
```

**ทำไมต้องเก็บทั้งสี่ค่า ทั้งที่คำนวณกลับได้:**

ถ้าไม่เก็บแล้วไปคำนวณใหม่ตอนเปิดดู วันที่รัฐเปลี่ยนอัตราจาก 7% เป็น 10%
**ใบขายเก่าทั้งหมดจะเปลี่ยนตัวเลขตามทันที** ใบที่พิมพ์ส่งลูกค้าไปแล้วเมื่อปีก่อนจะไม่ตรงกับ
ที่เก็บไว้ในระบบ และงบที่ปิดไปแล้วจะขยับ

**เอกสารทางบัญชีคือหลักฐาน ต้องคงสภาพ ณ วันที่ออก** ไม่ใช่ผลลัพธ์ที่คำนวณสดทุกครั้ง

หลักเดียวกันนี้ใช้กับ: ราคาขาย · ต้นทุน · ชื่อและที่อยู่ลูกค้า · ชื่อผู้ทำรายการ —
ทุกอย่างที่พิมพ์ลงเอกสารต้องถูก "ถ่ายภาพ" เก็บไว้ ไม่ใช่อ้างอิงไปหาตารางแม่

# 5. ค่าตั้งต้นต้องไหลลงมาถูกทาง

```
ตอนเปิดใบใหม่:
  ติ๊ก "คิด VAT"        ← ตั้งต้นจาก customers.apply_vat ของลูกค้าที่เลือก
  ติ๊ก "ราคารวม VAT"    ← ตั้งต้นจาก companies.default_vat_type
  อัตรา                 ← จาก companies.vat_rate (แสดงให้เห็น ไม่ให้แก้รายใบ)
```

**★ ผู้ใช้เปลี่ยนติ๊กได้เฉพาะใบนั้น ห้ามให้ไปแก้ค่าของลูกค้า**

การเปลี่ยนค่าตั้งต้นระยะยาวต้องเป็นการตัดสินใจที่ตั้งใจ ทำในหน้าจัดการข้อมูลลูกค้า
ไม่ใช่ผลข้างเคียงจากการติ๊กช่องตอนเปิดใบขายใบเดียว

**ค่าว่างต้องแปลว่า "คิด VAT"** ไม่ใช่ "ไม่คิด"

```js
// ค่าว่าง = เปิด เพราะค่าตั้งต้นของระบบคือคิด VAT (แถวเก่าที่มีก่อนฟีเจอร์นี้จะเป็นค่าว่าง)
function _vatBool(v) {
  if (v === '' || v === null || v === undefined) return true;
  var s = String(v).trim().toLowerCase();
  return !(s === 'false' || s === '0' || s === 'no');
}
```

ลูกค้าที่มีอยู่ก่อนเพิ่มฟีเจอร์นี้จะมีช่องว่าง ถ้าตีความว่า "ไม่คิด VAT" ลูกค้าเก่าทั้งหมด
จะหยุดคิด VAT พร้อมกันในวันที่ deploy โดยไม่มีใครสั่ง

**★★ ตัวแปลงค่าต้องมีตัวเดียวในระบบ** — เคยมีบั๊กจากการใช้ตัวแปลงของ `is_active`
มาแปลง `apply_vat` เพราะหน้าตาคล้ายกัน แต่ค่าว่างของสองเรื่องนี้ควรแปลผลต่างกัน
(`is_active` ว่าง = ใช้งานได้, `apply_vat` ว่าง = คิด VAT) บังเอิญตรงกันเลยไม่มีใครเห็น
จนวันที่มันไม่ตรง

# 6. สูตรคำนวณต้องมีชุดเดียว

```js
// คำนวณยอดรวม + VAT — ใช้ร่วมกันทั้งตอนสร้างและตอนแก้ไข จะได้ไม่มีสูตรสองชุดให้หลุดกัน
function _soComputeTotals(items, discountRaw, applyVatRaw, vatTypeRaw, vatRateRaw) { ... }
```

ฟังก์ชันนี้ถูกเรียกจากสามที่ — สร้างใบขาย · แก้ไขใบขาย · นำเข้าจากแพลตฟอร์ม

**ถ้าเขียนสูตรซ้ำในแต่ละที่** วันที่ต้องแก้ (เช่นเพิ่มการจัดการส่วนลดท้ายบิล) จะมีที่ใดที่หนึ่ง
ถูกลืม แล้วใบขายที่มาจากทางนั้นจะคิดเงินคนละแบบกับทางอื่น — โดยไม่มีอะไรฟ้อง

**ลำดับการคำนวณต้องชัด**

```
ยอดรวมรายการ   = Σ (ราคา − ส่วนลดรายบรรทัด) × จำนวน
ฐานคิด VAT     = ยอดรวมรายการ − ส่วนลดท้ายบิล
VAT            = คิดจากฐานตามสูตรใน ข้อ 2
```

ส่วนลดหักก่อนคิด VAT เสมอ — คิด VAT ก่อนแล้วค่อยหักส่วนลดจะได้ VAT เกินจริง

# 7. ถ้าต้องคิด VAT แยกรายบรรทัด (ส่วนที่ Hippo ยังไม่ได้ทำ)

ถ้า TOPSHOP มีสินค้ายกเว้น VAT ปนอยู่ในใบเดียวกัน ต้องเปลี่ยนโครงตามนี้

```
1. แยกยอดเป็นสองฐาน
     ฐานที่คิด VAT     = Σ บรรทัดที่ vat_applicable = true
     ฐานที่ยกเว้น       = Σ บรรทัดที่ vat_applicable = false

2. คิด VAT จากฐานแรกอย่างเดียว

3. ★ เก็บ vat_applicable ลงในแถว sales_items ด้วย ไม่ใช่อ่านจากตารางสินค้าตอนแสดงผล
     (หลักเดียวกับข้อ 4 — วันที่สินค้าเปลี่ยนสถานะ ใบเก่าต้องไม่เปลี่ยนตาม)

4. เอกสารต้องแยกให้เห็นสองยอด เพราะใบกำกับภาษีตามกฎหมายต้องแสดงแยก
     มูลค่าที่ต้องเสียภาษี   xxx
     มูลค่าที่ได้รับยกเว้น   xxx
```

**อย่าใช้วิธีตั้งธงเดียวทั้งใบแล้วบอกให้ผู้ใช้แยกเปิดสองใบ** — พนักงานจะลืม และของที่ยกเว้น
มักมีไม่กี่ตัวจนไม่มีใครจำได้ว่าตัวไหน

# 8. การแสดงผลบนเอกสาร

**ถ้าคิด VAT ต้องแสดงสามบรรทัดเสมอ** ไม่ใช่แค่ยอดรวม

```
มูลค่าสินค้า           1,000.00
ภาษีมูลค่าเพิ่ม 7%        70.00
รวมทั้งสิ้น            1,070.00
```

**ต้องบอกอัตราบนเอกสาร** (`7%`) ไม่ใช่แค่จำนวนเงิน — คนอ่านต้องตรวจสอบย้อนได้

**ใบกำกับภาษีต้องมีตามกฎหมาย:** เลขประจำตัวผู้เสียภาษีของทั้งผู้ขายและผู้ซื้อ ·
ระบุ "สำนักงานใหญ่" หรือ "สาขาที่ ..." ของทั้งสองฝ่าย · เลขที่และวันที่ · คำว่า "ใบกำกับภาษี"

**★ เลขผู้เสียภาษี 13 หลักต้องเก็บเป็นข้อความ** — Google Sheets และ Excel จะกลืนเลขศูนย์
นำหน้าทิ้ง `0105552018639` จะกลายเป็น `105552018639` แล้วใบกำกับภาษีผิดแบบเงียบ ๆ
ตั้งรูปแบบคอลัมน์เป็นข้อความล้วน และมีฟังก์ชันเติมศูนย์กลับตอนอ่านด้วย (กันสองชั้น)

**ถ้าไม่คิด VAT อย่าพิมพ์บรรทัด VAT ที่เป็นศูนย์** — พิมพ์ `ภาษีมูลค่าเพิ่ม 0.00` ทำให้ดูเหมือน
คิดแล้วแต่เป็นศูนย์ ซึ่งคนละความหมายกับไม่อยู่ในระบบ VAT

# 9. การปัดเศษ

```js
vatAmount = Math.round((beforeVat * vatRate) * 100) / 100;   // ปัดเป็นสตางค์ทันที
```

**ปัดที่จุดเดียวคือตอนได้ยอด VAT แล้ว** ไม่ใช่ปัดทุกบรรทัดแล้วค่อยรวม — ปัดหลายรอบทำให้
ยอดเพี้ยนสะสมจนไม่ตรงกับที่ลูกค้าคำนวณเอง

**ยอดรวมต้องบวกกลับได้เป๊ะ** ฐาน + VAT = ยอดรวม ถ้าปัดแล้วเกินมาหนึ่งสตางค์
ให้โยนส่วนต่างไปที่ยอดใดยอดหนึ่งอย่างตั้งใจ ไม่ใช่ปล่อยให้ค้าง

## สามข้อที่ถ้าจำได้แค่นี้ก็พอ

1. **inclusive กับ exclusive คนละสูตร** — ถามให้ชัดว่าราคาที่มีอยู่รวม VAT แล้วหรือยัง
2. **เอกสารต้องเก็บ VAT เป็นภาพนิ่ง** — อัตราเปลี่ยนวันไหน ใบเก่าต้องไม่ขยับตาม
3. **ค่าตั้งที่ตั้งแล้วไม่ถูกใช้ อันตรายกว่าไม่มีค่าตั้งเลย** — เพราะคนเชื่อว่าตั้งแล้ว

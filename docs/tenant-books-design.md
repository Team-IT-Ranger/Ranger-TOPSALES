# สมุดบัญชีของตัวแทนจำหน่าย — ร่างโครง (2026-10-06)

> **ยังไม่ได้ลงมือ** — ร่างให้เจ้าของระบบตัดสินใจก่อน · ข้อที่ต้องชี้ขาดอยู่ท้ายไฟล์

## โจทย์

เจ้าของระบบ (6 ต.ค. 2026): **ตัวแทน "ซื้อขาด" ไปจากบริษัท** พอขายต่อให้ลูกค้าของเขา
รายได้ก้อนนั้นเป็นของเขาทั้งก้อน **ต้องออกบิลและลงบัญชีในระบบของเขาเอง ไม่เกี่ยวกับบริษัทเลย**

ตอนนี้ระบบบัญชีทั้งโมดูลเป็นสมุดของบริษัทชุดเดียว ตัวแทนจึงยังทำบัญชีในระบบนี้ไม่ได้เลย

## สิ่งที่มีอยู่แล้ว — มากกว่าที่คิด

ก่อนออกแบบ ต้องรู้ว่า **ครึ่งหนึ่งของข้อมูลที่ต้องใช้ ไหลอยู่แล้ว**

| มีแล้ว | สภาพ |
|---|---|
| งานซื้อของตัวแทนครบสาย (PR/PO/GR/คลัง/ต้นทุนเฉลี่ย) | ทุกตารางมี `tenant_id` · แยกข้อมูลด้วย `_scoped()/_findScoped()` |
| นำเข้ารายการขายออกของบริษัท → PO+GR ของตัวแทน (`43_external_sales_import.gs`) | **เอกสารซื้อของตัวแทนถูกสร้างให้อัตโนมัติอยู่แล้ว** |
| บิลขายของตัวแทน (`sales_orders` ในไฟล์ตัวแทน) | ครบ รวม VAT ภาพนิ่ง ส่วนลด ของแถม |
| เลขเอกสารแยกเล่มต่อตัวแทน | `_nextCentralDocNo(type, scope)` → `PO-TNKN-202610-0001` ใช้ได้ทันทีกับ JV/INV/AP |
| ผังบัญชี + `_postJournal` ที่บังคับเดบิต=เครดิต | ใช้ซ้ำได้ ไม่ต้องเขียนใหม่ |

**ที่ขาดคือชั้นเดียว: การลงบัญชี** — ใบรับของของตัวแทนวันนี้ `journal_id` ว่างโดยตั้งใจ
ถ้าเติมมิติ "สมุด" ให้โมดูลบัญชี ของที่ไหลอยู่แล้วจะลงสมุดของเขาได้ทันที

## ทางเลือกโครงสร้าง

### ก. เพิ่มมิติ "สมุด" ลงตารางบัญชีกลาง ★ เสนอทางนี้

เพิ่ม `tenant_id` (ว่าง = สมุดบริษัท) ให้ `gl_journals` · `gl_journal_lines` · `ap_bills` · `ap_payments` ·
`ar_invoices`(มีแล้ว) · `ar_receipts` แล้วกรองทุกการอ่าน/เขียนผ่านตัวช่วยตัวเดียว

- **ตรงกับแพทเทิร์นที่โปรเจกต์ใช้อยู่แล้วทั้งโมดูลงานซื้อ** (`_scoped`) คนที่เคยอ่านโค้ดส่วนนั้นอ่านส่วนนี้ออกทันที
- รายงานทุกตัว (งบทดลอง/กำไรขาดทุน/งบดุล/อายุหนี้) แก้ที่เดียว: ใส่ตัวกรอง
- ข้อมูลเดิมไม่ต้องย้าย — `tenant_id` ว่างแปลว่าสมุดบริษัท ซึ่งถูกต้องอยู่แล้วทุกแถว
- **ข้อเสีย**: ทุกสมุดอยู่ในชีตเดียวกัน ความแยกเป็นเรื่องของโค้ด ไม่ใช่ของไฟล์ · ลืมกรองที่ไหน = ข้อมูลข้ามสมุด
  → แก้ด้วยการบังคับทุกทางเข้าให้ผ่านตัวช่วยตัวเดียว เหมือนที่งานซื้อทำ และเขียนเทสต์คุมการรั่วข้ามสมุด

### ข. ย้าย journal ไปไว้ในไฟล์ของตัวแทนแต่ละราย

- แยกขาดจริงระดับไฟล์
- **ข้อเสียหนัก**: เปิดไฟล์ตัวแทน ≈ 1.5–2.7 วินาที **ต่อหนึ่งรายงาน** · ฝั่งบริษัทจะดูภาพรวมข้ามตัวแทน
  ต้องเปิด N ไฟล์ · โค้ดรายงานทั้งหมดต้องเขียนใหม่ · `_postJournal` ต้องรู้จักสองที่เก็บ

### ค. Google Sheet แยกใบต่อตัวแทนเฉพาะงานบัญชี

- แยกขาดที่สุด เหมาะถ้าวันหนึ่งตัวแทนต้องส่งไฟล์ให้ผู้สอบบัญชีของตัวเอง
- หนักที่สุด: ต้องจัดการสิทธิ์/สำรองข้อมูล/สคีมาอีกชุด

**เสนอ ก.** เพราะได้ผลลัพธ์ที่ต้องการด้วยงานน้อยที่สุดและเข้ากับของเดิม ·
ถ้าวันหนึ่งต้องแยกไฟล์จริง (ข้อ ค.) การมี `tenant_id` อยู่แล้วทำให้ย้ายออกง่ายกว่าไม่มี

## สิ่งที่จะลงในสมุดของตัวแทน

ตัวแทนซื้อขาดจากบริษัท → **ในสมุดของตัวแทน บริษัทคือ "เจ้าหนี้การค้า"**

| เหตุการณ์ | เดบิต | เครดิต | มีข้อมูลแล้วไหม |
|---|---|---|---|
| รับของจากบริษัท (GR) | 1300 สินค้าคงเหลือ | 2150 GR-NI | ✅ มี GR ของตัวแทนแล้ว |
| ตั้งหนี้บริษัท (AP) | 2150 + 1400 ภาษีซื้อ | 2100 เจ้าหนี้ | ✅ มี GR ให้ตั้งหนี้ |
| จ่ายเงินบริษัท | 2100 | 1120 ธนาคาร | ต้องทำ |
| **ขายให้ลูกค้าของเขา** | 1200 ลูกหนี้ | 4100 รายได้ + 2200 ภาษีขาย | ✅ มีบิลขาย + VAT ภาพนิ่ง |
| รับชำระจากลูกค้า | 1120 | 1200 | ต้องทำ |
| ต้นทุนขาย (COGS) | 5100 | 1300 | **ยังไม่มีทั้งสองสมุด** (ค้างมาแต่เดิม) |

## ลำดับที่เสนอให้ทำ

1. **มิติสมุด + ตัวช่วยกรอง + เทสต์กันข้อมูลข้ามสมุด** (ฐานของทุกข้อถัดไป)
2. **รายงานแยกตามสมุด** — งบทดลอง/กำไรขาดทุน/งบดุล/อายุหนี้ ของใครของมัน
3. **ขาซื้อของตัวแทน** — GR ลง journal + ตั้งหนี้บริษัท + จ่ายเงิน (ข้อมูลไหลอยู่แล้ว ได้ผลเร็วที่สุด)
4. **ขาขายของตัวแทน** — ปลดล็อก `_arTenantBlocked` ให้ลงสมุดของตัวแทนแทนการปฏิเสธ
5. **ตั้งหนี้+ใบกำกับภาษีอัตโนมัติตอน "พร้อมจัดส่ง"** (ข้อ 3 เดิม) — ทำได้ครบทั้งสองฝั่งตรงนี้

ทำถึงข้อ 3 ก็เริ่มใช้งานจริงได้แล้วสำหรับ BDC เพราะเอกสารซื้อของเขาไหลเข้าระบบอยู่ทุกวัน

## ★ ข้อที่ต้องให้เจ้าของระบบชี้ขาดก่อนลงมือ

1. **ผังบัญชี** — ใช้ผังเดียวกันทุกสมุด (ง่าย รายงานเทียบกันได้) หรือให้ตัวแทนมีผังของตัวเอง (ยืดหยุ่น แต่ต้องมีหน้าจอจัดการต่อตัวแทน)
2. **ยอดยกมา** — สมุดของ BDC เริ่มนับจากวันไหน · มียอดค้างเดิมจากระบบเก่าที่ต้องยกมาไหม หรือเริ่มจากศูนย์
3. **ใครเห็นสมุดของตัวแทน** — ตัวแทนเห็นของตัวเองอย่างเดียวแน่นอน แต่ **ฝั่งบริษัทควรเปิดดูได้ไหม**
   (ดูได้ = ช่วยตรวจ/ช่วยปิดงบให้เขาได้ · ดูไม่ได้ = แยกขาดตามหลักนิติบุคคล)
4. **ราคาทุนในสมุดตัวแทน** — ใช้ราคาที่เขาซื้อจากบริษัทจริง (มีใน PO/GR) ใช่ไหม
5. **ตัวแทนบันทึกรายการเองได้แค่ไหน** — ลงใบสำคัญทั่วไป (JV) เองได้ไหม หรือให้ระบบลงให้อัตโนมัติอย่างเดียว

## ที่ยังไม่อยู่ในร่างนี้

ปิดงวดบัญชี · ภาษีหัก ณ ที่จ่าย · รายงาน ภ.พ.30 · ต้นทุนขาย (COGS) ซึ่งค้างอยู่ในสมุดบริษัทเหมือนกัน
— ควรทำหลังโครงสมุดนิ่งแล้ว ไม่ใช่พร้อมกัน

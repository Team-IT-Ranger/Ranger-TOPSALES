# แผ่น 03 — ผังโครงสร้างข้อมูล

ข้อมูลอยู่ที่ไหน · คำว่า "ตัวแทน" มี 3 ความหมายที่ไม่เหมือนกัน · สคีมาเปลี่ยนตัวเองได้อย่างไร

## 1. ข้อมูลอยู่สองที่ และเส้นแบ่งไม่ใช่เรื่องรสนิยม

| | Central Sheet (1 ไฟล์ต่อ env) | ไฟล์ของตัวแทน (1 ไฟล์ต่อราย) |
|---|---|---|
| จำนวนชีต | 60 | 14 |
| เก็บอะไร | ทุกอย่างที่**ทั้งระบบใช้ร่วมกัน** หรือที่**บริษัทเป็นเจ้าของ** | **รายการขายและสต็อกรถของตัวแทนรายนั้น** |
| ตัวอย่าง | สินค้า · ลูกค้า · ชุดราคา · ผู้ใช้/บทบาท · ตัวแทน · งานซื้อ · บัญชีทั้งหมด | `sales_orders` · `order_items` · `van_stock` · `delivery_rounds` · ตัวนับเลขเอกสาร |
| อ่านด้วย | `centralObjects()` | `tenantRowById()` / `tenantRowsWhere()` / `tenantObjectsIfExists()` |

**เหตุผลที่แยก**: เปิดไฟล์หนึ่งไฟล์ใน Apps Script เสีย ~2 วินาที ถ้าเอารายการขายของทุกตัวแทน
มารวมไว้ไฟล์เดียว ทุกคำขอจะต้องอ่านของทุกคน · และตัวแทนเป็นคนละนิติบุคคล ข้อมูลขายของเขา
ไม่ควรนอนอยู่ไฟล์เดียวกับคู่แข่ง

**ผลที่ตามมา**: **แดชบอร์ดห้ามเปิดไฟล์ตัวแทน** — มันอ่านตาราง `sales_daily` ในชีตกลางแทน
จึงต้องเรียก **`bumpSalesDaily()` ทุกจุดที่บันทึก/ยกเลิกบิล** · ตัวเลขเพี้ยนซ่อมด้วย `rebuildSalesDaily()`
(ช้า เพราะเปิดไฟล์ทุกตัวแทน ใช้เฉพาะตอนซ่อม)

> รายชื่อชีตและคอลัมน์ทั้งหมดอยู่ใน [แผ่น 06 หมวด D](06-schedules.generated.md)

## 2. ★★ "ตัวแทน" สามความหมาย ห้ามยุบรวม

`tenant_id` ปรากฏในหลายตาราง แต่**ตอบคำถามไม่เหมือนกัน** และคิดค่ามาจากฟังก์ชันต่างตัวกัน:

| มิติ | ตอบคำถาม | คิดจาก | ใช้กับ |
|---|---|---|---|
| **ไฟล์ข้อมูล** | รายการขายนี้อยู่ไฟล์ไหน | รหัสตัวแทนตรงๆ | `sales_orders` ฯลฯ ในไฟล์ตัวแทน |
| **ขอบเขตงานซื้อ/คลัง** | ใบสั่งซื้อนี้ของใคร | `_purchaseScope()` = `_effectiveTenantId()` | ทุกตารางงานซื้อ/คลังในชีตกลาง |
| **สมุดบัญชี** | ใบสำคัญนี้อยู่สมุดใคร | `_bookScope()` | `gl_journals` · `ar_*` · `ap_*` |

- **ค่าว่าง = ของบริษัทเจ้าของสินค้า** (ไม่ใช่ "ของทุกคน") — แถวเดิมทุกแถวมีค่าว่าง จึงถูกต้องอยู่แล้วไม่ต้อง migrate
- **★ `HOUSE` / `TNKI` = ตัวแทนบ้าน** ยอดขายตรงของบริษัทเก็บผ่านตัวแทนบ้าน เอกสารจึงติด `tenant_id = 'TNKI'` มา
  ขณะที่แถวบัญชีเดิมมีค่าว่าง — **`_bookScope` ยุบสองค่านี้ให้เป็นสมุดเดียวกัน** ถ้าไม่ยุบ
  บริษัทจะมีสองสมุดโดยไม่มีใครสั่ง
- **ห้ามเรียก `centralObjects()` ตรงๆ กับตารางงานซื้อ/คลัง** ต้องผ่าน `_scoped()` / `_findScoped()`
  (`20_purchasing_master.gs`) ไม่งั้นข้อมูลข้ามบริษัทกัน
- **ไม่มี "รวมทุกสมุด"** โดยตั้งใจ — คนละนิติบุคคล งบรวมกันไม่มีความหมายทางบัญชี
- บัญชีที่**สังกัดตัวแทน** ข้ามไปตัวแทนอื่นไม่ได้เด็ดขาด · บัญชีของ**บริษัทกลาง** (`tenant_id` ว่าง)
  สวมสิทธิ์เข้าไปดูแลตัวแทนรายใดก็ได้ผ่าน `payload.tenantId` (`_effectiveTenantId`)
- เลขเอกสารแยกเล่มต่อบริษัท: ตัวนับคีย์ `'PO@BDC'` แยกจาก `'PO'` — **`central: true` หมายถึง
  "ที่เก็บตัวนับ" ไม่ใช่ "เลขเดินร่วมกัน"**

## 3. สคีมาเติมตัวเองได้ — แต่มีเงื่อนไข

| ที่ | กลไก | ข้อควรระวัง |
|---|---|---|
| ชีตกลาง | `ensureSchemaCurrent()` เทียบ**ลายนิ้วมือ** ของ `CENTRAL_SHEETS` + ลิสต์โมดูล | เพิ่มคอลัมน์/โมดูลใหม่ = ลายนิ้วมือเปลี่ยน → เติมเองตอนแอดมินล็อกอินครั้งถัดไป |
| ไฟล์ตัวแทน | `ensureTenantSheetsCurrent(tenantId)` เติม tab/คอลัมน์ที่ขาด | **★ ต้องเรียกก่อนทุกจุดที่เขียนคอลัมน์ใหม่** ไม่งั้นค่าถูกทิ้งเงียบๆ เพราะเขียนด้วยชื่อหัวคอลัมน์ |

- `ensureTenantSheetsCurrent` กันซ้ำด้วยลายนิ้วมือใน CacheService (ตรวจจริงอย่างมาก 6 ชม./ตัวแทน)
  · สั่งทั้งระบบทันทีด้วย action `syncTenantSheets` (super_admin)
- `_ensureColumns()` เติมคอลัมน์ทีหลังได้ฟรี → **จึงไม่เพิ่มคอลัมน์ที่ยังไม่มีโค้ดไหนอ่าน**
  ฟิลด์ที่ยังไม่ตกผลึกไปพักที่ `customers.attributes` (JSON) ก่อน
- **ค่าว่างต้องแปลว่า "เหมือนเดิม" ทุกครั้ง** นี่คือเหตุผลที่ไม่เคยต้อง migrate:
  `is_stock`/`is_sellable` ว่าง = ใช่ · `tax_status` ว่าง = คิด VAT · `no_discount` ว่าง = ลดได้ (ตรงข้าม จึงต้องติ๊กชัดเจน)

## 4. กับดักของ Google Sheets ที่กัดเราแล้วทุกตัว

| อาการ | สาเหตุ | กันด้วย |
|---|---|---|
| `'TRUE'` กลายเป็น boolean `true` | Sheets แปลงชนิดเอง | `isFlagOn/isFlagOff/isNotOff` (`02_helpers.gs`) **ห้ามเทียบ `String(x)==='TRUE'`** |
| เลขผู้เสียภาษีศูนย์นำหน้าหาย | Sheets อ่านเป็นตัวเลข | `_setTextColumns()` ที่ customers/company_profile/tenants/vendors |
| เขียน 2,000 แถวแล้วชน 6 นาที | `centralUpdate` ทีละแถว | **`updateColumnsWhere()`** เขียนครั้งเดียวต่อคอลัมน์ |
| ค่าที่เขียนไปหายเงียบ | ชีตยังไม่มีคอลัมน์นั้น | `ensureTenantSheetsCurrent` ก่อนเขียน |
| อ่านได้ของเก่า | แคชข้ามคำขอยังไม่หมดอายุ | เขียนผ่าน `centralAppend/Update/...` หรือเรียก `centralInvalidate()` เอง |
| VAT ต่างกันทีละสตางค์ | ปัดเศษคนละที่ | **`splitVat()` ที่เดียว** (ดูแผ่น 05) |

## 5. ข้อมูลที่ยกมาจากระบบเดิม

สองแฟ้มที่เป็นต้นทางของทะเบียนจริง (อยู่ใน `reference/` บน Shared Drive — **ไม่ขึ้น GitHub**):

| แฟ้ม | จาก | จำนวน | สถานะ |
|---|---|---|---|
| `ARMAS.DBF` | โปรแกรมบัญชี Express (TIS-620) | 1,106 ราย | นำเข้าแล้ว (`external_system = express`) |
| `customer_for_bdc.xlsx` | โปรแกรมขายเดิมที่ตัวแทนใช้ | 2,039 ราย | นำเข้าแล้ว (`external_system = bdc`) |
| `STMAS.DBF` | item master ของ Express | 1,054 รายการ | ใช้เป็นแหล่งอ้างอิงฟิลด์สินค้า |

- ทับด้วย `external_code` คู่กับ `external_system` → **รันสคริปต์นำเข้าซ้ำได้ไม่เกิดแถวซ้ำ**
- รหัสของระบบเดิมที่ยังไม่ map เข้าตารางอ้างอิงของเรานอนอยู่ใน `attributes.source*`
- **★ เลือกกลุ่มปลายทางจาก "กลุ่มที่มีชุดราคาเปิดใช้งานอยู่" ไม่ใช่จากชื่อกลุ่ม** — UAT มีกลุ่มชื่อ
  เกือบเหมือนกันสองตัวต่างกันแค่ `/` กับ `,` จัดร้านเข้ากลุ่มผิด = ร้านเปิดบิลไม่ได้
  และ**ไม่มีอะไรฟ้องจนกว่าพนักงานขายจะเปิดบิลไม่ได้หน้าร้าน**

## 6. ยังไม่ก่อสร้าง

- **`ShopTypeCode` → `channel_id` ยังไม่ map** (PS 1,050 · MM 344 · "ไม่แน่ใจ" 553 …) รอเจ้าของระบบ
- **2 ร้านยังไม่มีกลุ่ม = ขายไม่ได้** (`C1492` · `C1991`) ต้นทางไม่มีจังหวัด
- ฟิลด์ที่เห็นในระบบเดิมแล้วยังไม่เอามา: `PAYER` (ผู้ชำระเงินแทน) · `SHIPTO` หลายที่อยู่ ·
  `TABPR` ชุดราคาเฉพาะราย · `ACCCOD` รหัสบัญชีรายสินค้า · หมวดสินค้าสองชั้น · การจัดการล็อต
- **`customers.tax_type` ยังไม่มีใครอ่าน** — ภาษีตอนนี้ตัดสินจากสินค้าอย่างเดียว

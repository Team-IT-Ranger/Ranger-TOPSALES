# ชุดแบบของระบบ Ranger TOPSALES

เอกสารชุดนี้คือ **แบบก่อสร้าง** ไม่ใช่คู่มือผู้ใช้และไม่ใช่บันทึกการทำงาน
หน้าที่ของมันคือตอบคำถามว่า *ของชิ้นนี้อยู่ที่ไหน · ต่อกับอะไร · ห้ามแตะอะไร*
ก่อนจะลงมือแก้ ไม่ใช่หลังจากแก้เสร็จแล้ว

## แผ่นแบบ

| แผ่น | ตอบคำถาม |
|---|---|
| [01 — ผังบริเวณ](01-site-plan.md) | ระบบอยู่บนอะไร · 3 สภาพแวดล้อมแยกกันอย่างไร · ทางเข้ามีกี่ทาง · ตัวตนของผู้ใช้มาจากไหน |
| [02 — ผังพื้น](02-floor-plan.md) | โค้ด 25,000 บรรทัดจัดเป็นชั้นอะไร · หน้าจอมีกี่หน้าและใครเห็นหน้าไหน |
| [03 — ผังโครงสร้าง](03-structure.md) | ข้อมูลอยู่ที่ไหน · "ตัวแทน" 3 ความหมายที่ไม่เหมือนกัน · สคีมาเปลี่ยนตัวเองได้อย่างไร |
| [04 — ผังระบบ](04-systems.md) | เส้นทางงานจริง 7 เส้น เดินจากต้นถึงปลายทีละขั้น |
| [05 — สัญญาที่ห้ามแตะ](05-contracts.md) | **อ่านแผ่นนี้ก่อนเขียนโค้ด** จุดที่มีตัวเดียวในระบบ ใครเขียนตัวที่สองคือพัง |
| [06 — รายการประกอบแบบ](06-schedules.generated.md) | รายการทั้งหมด: action · ตาราง · คอลัมน์ · สิทธิ์ · เอกสาร · เมนู · เทสต์ |

## วิธีอ่าน

- **แก้ของที่มีอยู่แล้ว** → แผ่น 05 ก่อน (แก้โดนสัญญาข้อไหนหรือเปล่า) แล้วค่อยแผ่น 04 (อยู่ในเส้นทางไหน)
- **เพิ่มของใหม่** → แผ่น 02 (วางไว้ชั้นไหน) + แผ่น 03 (ข้อมูลเก็บที่ไหน) + ท้ายแผ่น 05 (รายการที่ต้องไปลงทะเบียน)
- **หาว่าของชิ้นหนึ่งอยู่ไฟล์ไหน** → แผ่น 06
- **หาว่าทำไมมันเป็นแบบนี้** → [`../../CLAUDE.md`](../../CLAUDE.md) เป็นบันทึกบทเรียนเรียงตามเวลา
  ที่เจอปัญหา ลึกกว่าแบบในรายละเอียด · แบบชุดนี้สรุปเฉพาะที่มีผลต่อการตัดสินใจเชิงโครงสร้าง

ลึกลงไปอีกชั้นมีคู่มือเฉพาะเรื่องที่**ต้องอ่านก่อนแตะเรื่องนั้น**:
[ราคา](../pricing-architecture.md) · [VAT](../vat-configuration-guide.md) ·
[สถานะบิลและการพิมพ์](../sales-status-and-printing-guide.md) · [สมุดบัญชีตัวแทน](../tenant-books-design.md)

## แบบนี้จะไม่เก่า เพราะ

แผ่น 06 **สร้างจากโค้ดจริงทุกครั้ง** ไม่ได้พิมพ์มือ:

```bash
node .dev/gen-blueprint.js
```

และเช็คได้ว่าแบบยังตรงกับโค้ดอยู่หรือไม่ (ใช้ก่อน commit — ออกจากโปรแกรมด้วย exit code 1 ถ้าไม่ตรง):

```bash
node .dev/gen-blueprint.js --check
```

> ในสามสัปดาห์ (แก้ล่าสุด 19 ก.ย. 2026 ก่อนจะมีงานซื้อ บัญชี สมุดตัวแทน รอบจัดส่ง ใบลดหนี้ ทั้งหมด)
> `docs/who-is-doing-what.md` ก็เคยโกหกว่ากุญแจว่างจนต้องเขียนกฎ "บรรทัดเก่ากว่า 2 วันถือว่าปล่อยแล้ว"
> มาแปะ · บทเรียนในไฟล์เราเองเขียนไว้ว่า **"กติกาในเอกสารไม่ช่วยถ้าไม่มีกลไกบังคับ"**
> — **แบบที่โกหกแย่กว่าไม่มีแบบ เพราะคนทำงานตามแบบ**

**เปลี่ยนโครงสร้างเมื่อไหร่ ต้องแก้แผ่นที่เกี่ยวในคอมมิตเดียวกับโค้ด** ไม่ใช่ตามไปแก้ทีหลัง

# แผ่น 05 — สัญญาที่ห้ามแตะ

**อ่านแผ่นนี้ก่อนเขียนโค้ด** · ทุกข้อในนี้มาจากของที่เคยพังจริง ไม่ใช่ความชอบส่วนตัว

อาการร่วมของทุกข้อคือ **ผิดแล้วไม่มีอะไรฟ้อง** — ไม่มี error ไม่มีหน้าแดง ตัวเลขผิดเงียบๆ
แล้วไปโผล่ตอนปิดงบ หรือตอนพนักงานขายเปิดบิลไม่ได้หน้าร้าน

## 2. ข้อตกลงเรื่องข้อมูลที่ต้องเป็นจริงเสมอ

1. **ค่าว่างแปลว่า "เหมือนเดิม"** — `is_stock`/`is_sellable`/`is_purchasable`/`tax_status` ว่าง = ใช่/คิดภาษี
   · ข้อยกเว้นเดียวคือ `no_discount` ที่กลับทาง (ว่าง = ลดได้) เพราะต้องติ๊กชัดเจนถึงจะห้าม
   → นี่คือเหตุผลที่ระบบนี้**ไม่เคยต้อง migrate ข้อมูล** เมื่อเพิ่มคอลัมน์
2. **`tenant_id` ว่าง = ของบริษัท ไม่ใช่ "ของทุกคน"** · และ `HOUSE`/`TNKI` = สมุดเดียวกับบริษัท
3. **`subtotal − discount = total` เสมอ** (`sales_orders.discount` เก็บส่วนลดรวมทุกชั้น)
4. **`subtotal_ex_vat + vat_amount = total` เป๊ะเสมอ** ทุกบิล ทุกรอบจัดส่ง ทุกใบลด/เพิ่มหนี้
5. **ผลรวมทุกรอบจัดส่ง = ยอดบิลเป๊ะ** ทั้งสามค่า (รอบสุดท้ายรับเศษที่เหลือ)
6. **บิลเก็บภาพนิ่งภาษีตั้งแต่ตอนบันทึก ห้ามคำนวณใหม่ตอนเปิดดู** · `order_items` ก็เก็บราคาที่ขายจริง
   และ `tax_status` รายบรรทัดด้วย → **แก้ชุดราคาแล้วบิลเก่าไม่กระทบ**
7. **ยกเลิกใบสำคัญ = ออกใบกลับรายการ ไม่ลบของเดิม** → งบทดลองนับทุกใบรวมใบที่ voided
8. **ประวัติไม่ลบ ไม่ทับ** — `order_status_log` · `pr_approvals` · `price_list_change_log`
9. **ชุดราคา `archived` แก้ไม่ได้** (`draft`/`active` แก้ได้ แต่ `active` ต้องเขียน `price_list_change_log`
   ทุกครั้งผ่าน **`_logPriceChange()`**)
10. **เงื่อนไขว่าง = ไม่ผ่าน ไม่ใช่ "ทุกคน"** ใช้กับกฎสิทธิ์ · การจัดกลุ่มเป็นชุด · การจ่ายชุดให้ตัวแทน

## 3. เพิ่มของใหม่ = ต้องไปลงทะเบียนที่ไหน

**★ ลืมข้อใดข้อหนึ่งแล้วจะเงียบ ไม่มี error** — นี่คือเช็คลิสต์ที่เสียเวลาที่สุดถ้าลืม

| เพิ่มอะไร | ต้องไปแก้ |
|---|---|
| **action ใหม่** | `ACTION_MAP` หรือ `ADMIN_ACTION_MAP` (`05_router.gs`) |
| **action ที่เขียนข้อมูล** | + `MUTATING_ACTIONS` (หน้าเว็บ) · ถ้าสร้างเอกสารใหม่ + `IDEMPOTENT_ACTIONS` **ทั้งสามที่** · ครอบด้วย `_withDocLock()` |
| **ตารางใหม่** | `CENTRAL_SHEETS` (`00_setup_sheets.gs`) หรือ `TENANT_SHEET_TABS` (`13_tenants.gs`) |
| **คอลัมน์ใหม่ในไฟล์ตัวแทน** | + เรียก **`ensureTenantSheetsCurrent()` ก่อนเขียน** |
| **เขียนชีตแบบดิบ** | + `centralInvalidate('<ชีต>')` เอง |
| **จุดที่บันทึก/ยกเลิกบิล** | + `bumpSalesDaily()` (ไม่งั้นแดชบอร์ดเพี้ยน) |
| **จุดที่แก้ราคาในชุดที่ active** | + `_logPriceChange()` |
| **เอกสารที่มีเลขกำกับ** | `DOC_SERIES_TYPES` (`12_docnum.gs`) — `defaults` ต้องให้ผล**เหมือนที่ระบบออกมาแต่ไหนแต่ไร เป๊ะทุกตัวอักษร** |
| **เมนูใหม่** | `NAV_GROUPS` + `ICONS` (`index.html`) + ใส่ **`scope`** ทุกครั้ง + โมดูลต้องอยู่ใน `OWNER_MODULES`/`TENANT_MODULES` |
| **โมดูลสิทธิ์ใหม่** | `OWNER_MODULES`/`TENANT_MODULES`/`TENANT_VIEW_ONLY_MODULES` (`00_setup_sheets.gs`) — ลายนิ้วมือสคีมาเปลี่ยน แล้วสิทธิ์จะถูกเติมเอง |
| **ชนิดชุดที่จ่ายให้ตัวแทน** | `PKG_TYPES` (`38_package_distribution.gs`) ที่เดียว |
| **ฟิลด์เงื่อนไขกฎสิทธิ์** | `PLR_FIELDS` + `plrFieldChoices()` (`36_price_rules.gs`) — **field เป็น whitelist** ถ้าฟิลด์อ้างตารางต้องใส่ `choices` ด้วย ไม่งั้นคนตั้งค่าพิมพ์ "ชื่อ" ลงช่องที่เก็บ "รหัส" แล้วกฎเงียบ |
| **คอลัมน์ที่แก้เป็นชุดได้** | `CB_SETTABLE` (`37_customer_bulk.gs`) |
| **ขนาดกระดาษใหม่** | `setPaper()` **ทั้งในแอปและไฟล์ที่เปิดแท็บใหม่** |
| **รายการที่จำข้ามการเปิดแอป** | `listSnapSave()` + **ถ้าย่อฟิลด์ ต้องกั้นไม่ให้แถวที่ย่อหลุดเข้าฟอร์มแก้ไข** |
| **ป้ายสถานะบิล** | `SO_STATUS_LABELS` (backend) **และ** `SO_LABELS`/`PAY_LABELS` (หน้าเว็บ) ต้องตรงกัน |
| **อะไรก็ตามข้างบนนี้** | `node .dev/gen-blueprint.js` แล้ว commit แผ่น 06 ไปด้วย |

## 4. วิธีทำงานที่ตกลงกันแล้ว

1. **ทุกอย่างลงกิ่ง `UAT`** · `main` ขยับด้วย `git merge UAT --ff-only` เท่านั้น และต่อเมื่อเจ้าของระบบอนุมัติ
2. **เจ้าของ deployment กด Deploy เอง** Claude แค่ `clasp push` — `clasp deploy` ข้ามโดเมน Workspace ไม่ได้
3. **ห้ามทำงานในโฟลเดอร์ `G:\Shared drives\...`** Google Drive ไม่ merge ไฟล์ที่ถูกเขียนพร้อมกัน
   มันสร้างไฟล์คู่ขนานแทน · `.git/index` โดนก่อน แล้ว repo เสียทั้งก้อน (เคยเจอจริง: `index (1)` ใน `.git`)
   · **ช่องทางแชร์คือ GitHub เท่านั้น** · `G:` เหลือบทบาทเป็นที่เก็บ `reference/` (ใบราคาจริง — ไม่ขึ้น GitHub)
4. **จับ/ปล่อยกุญแจที่ `docs/who-is-doing-what.md`** — `frontend-admin/index.html` กุญแจดอกเดียว ·
   `clasp push` กุญแจดอกเดียว (push ตอนอีกคนกำลังเทสต์ = เขาเทสต์โค้ดเราโดยไม่รู้ตัว)
5. **ตรวจว่าใช้งานได้จริงก่อนรายงานว่าเสร็จ** — เทสต์หน่วย + เดินของจริงบน UAT ไม่ใช่ "น่าจะได้แล้ว"
6. **ไฟล์เป็น CRLF และมีภาษาไทย** → ใช้ Write/Edit หรือสคริปต์ Python แบบไฟล์
   **ห้ามใช้ bash heredoc กับข้อความไทย** (พังมาแล้วหลายครั้ง)
7. **เช็คไวยากรณ์ก่อน push ทุกครั้ง**: `node --check` บน `.gs` ที่ต่อกัน และบน `<script>` ที่ดึงออกจาก `index.html`

## 5. บทเรียนเรื่องการเทสต์ที่แพงที่สุด

- **เทสต์เรื่องตารางต้องใช้ตารางที่กว้างที่สุดในระบบ** ไม่ใช่ตารางที่สร้างเองให้พอดีจอ
  (บั๊ก colspan โผล่เฉพาะหน้าสินค้า 18 คอลัมน์ ผู้ใช้เห็นก่อน)
- **เทสต์กรณีปฏิเสธต้องเช็คข้อความที่ตอบกลับด้วย ไม่ใช่แค่ `!success`** — ส่ง payload ผิดรูป
  แล้วมันตอบ "ยังไม่ได้เลือกใบแจ้งหนี้" ซึ่งหน้าตาเหมือนการปฏิเสธที่เราต้องการ
  → **เทสต์ผ่านโดยไม่ได้ทดสอบอะไรเลย** (15 ต.ค. 2026)
- **สคริปต์ที่ยิง UAT ให้เลือกสินค้าที่สต็อกน้อยที่สุด** — หยิบตัวที่ของเยอะแล้วได้บิลทดสอบ
  เจ็ดแสนบาทค้างในระบบจริง ต้องตามเก็บกวาดทั้งยกเลิกบิล คืนของด้วยใบรับของ และกลับรายการบัญชี
- **mock ชีตต้องเป็นตาราง 2 มิติจริง** ถ้า mock เป็น array ของ object ตัวเขียนแบบคอลัมน์
  (`updateColumnsWhere`) จะไม่เคยถูกรันเลย
- **อย่าเชื่อว่าความคาดหมายของเราถูก** — เคยเขียนเทสต์ว่า "ไฟควรเป็นสีส้ม" แล้วสงสัยโค้ด
  ทั้งที่บิลอื่นถือสต็อกไว้จริง ไฟแดงถูกแล้ว

- **★★ มี "ทางที่สอง" เข้าสู่สถานะเดียวกันเมื่อไหร่ ต้องไล่ว่าผลข้างเคียงของทางแรกถูกทำครบไหม**
  บั๊ก `DRAFT-` บน prod เกิดจากสองทางที่พาบิลออกจากร่าง แต่ออกเลขเอกสารอยู่ทางเดียว —
  **ไม่มี error ไม่มีอะไรฟ้อง** รู้ตอนเจ้าของระบบเห็นเลขแปลกๆ ในตารางเอง

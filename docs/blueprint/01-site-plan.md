```

     │

     │                                                      └─ uat.ranger-topsales-admin.pages.dev
     ├── พนักงานขาย (LINE LIFF ในมือถือ) ── Cloudflare Pages ── ranger-topsales-mobile.pages.dev

                     ▼
   ┌──────────────────────────────────────────────┐
```

เปลี่ยนฐานข้อมูลจาก Sheets ไปเป็นอย่างอื่นวันหนึ่งได้โดยหน้าเว็บไม่ต้องรู้เรื่อง

## 2. สามสภาพแวดล้อม แยกขาดกันทุกชั้น

| | dev | uat | prod |
|---|---|---|---|
| กิ่ง git | — | `UAT` | `main` (ff-only จาก UAT) |
| Apps Script | `1iVJDVuc…` | `1SDBJgSN…` | `1XObaZXu…` |
| ไฟล์ตั้งค่า clasp | `.clasp.dev.json` | `.clasp.uat.json` | `.clasp.prod.json` |
| Central Sheet | ของ dev | ของ uat | ของ prod |
| โฟลเดอร์ Drive | (ยังไม่จัด) | `db_uat/` | `db_prod/` |
| โฮสต์แอดมิน | — | `uat.ranger-topsales-admin.pages.dev` | `ranger-topsales-admin.pages.dev` |
| ใช้ทำอะไร | สภาพแวดล้อมส่วนตัวของเจ้าของระบบ · **แอปนี้ไม่ใช้** | ที่เราทดสอบ | ของจริง |

**★ ห้ามให้สภาพแวดล้อมหนึ่งแตะโค้ดหรือข้อมูลของอีกสภาพแวดล้อมเด็ดขาด** — เคยพลาดมาแล้ว
ตอนที่รีโปเรียก dev ว่า "production" แล้ว `/admin/` ถูกต่อไปที่ backend ของ dev

**ค่าที่ต่างกันรายสภาพแวดล้อมไม่มีอยู่ในโค้ดเลย** อยู่ใน Script Properties ของแต่ละโปรเจกต์ล้วนๆ:
`CENTRAL_SHEET_FILEID` · `ENV_NAME` · `LINE_CHANNEL_ID` · `LINE_CHANNEL_SECRET` · `LIFF_ID` ·
`ENDPOINT_URL` · `DB_ROOT_FOLDER_ID`
· property **ไม่ติดไปกับการคัดลอกโปรเจกต์** จึงต้องตั้งใหม่ทุกครั้งที่สร้าง env ใหม่
· `ENV_NAME` ไม่ได้ตั้ง = ถือว่าเป็น prod (เข้มที่สุดโดยค่าตั้งต้น)

### ★ แอปรู้ว่าตัวเองเป็น env ไหนจาก **ชื่อโฮสต์** ไม่ใช่ path

`config.js` ของทั้งสองแอป: hostname มีคำว่า `uat` หรือเป็น `localhost` → ใช้ backend ของ uat · นอกนั้น → prod

นี่คือเหตุผลที่ **GitHub Pages ถูกปิดเหลือแค่หน้าแจ้งย้าย** (30 ก.ย. 2026): โดเมน GitHub Pages
ไม่มีคำว่า uat อยู่เลย ทั้ง `/admin/` และ `/admin-uat/` จึงถูกตัดสินเป็น prod เหมือนกันทั้งคู่
= ใครเปิดลิงก์ UAT เก่าที่ค้างในเครื่องจะไป **เขียนข้อมูล production โดยไม่รู้ตัว**
หน้าแจ้งย้ายไม่โหลด `config.js` และไม่โหลดตัวแอปเลย จึงแตะ backend ไม่ได้ไม่ว่ากรณีใด

`frontend-*/_headers` สั่ง Cloudflare ว่า `/config.js` ต้อง `Cache-Control: no-store`
— ไม่งั้นผู้ใช้เดิมยังยิงไป backend ตัวเก่าหลัง deploy จนกว่าแคชเบราว์เซอร์หมดอายุ
(ตอนอยู่บน GitHub Pages ต้องคอยบัมป์ `?v=` เอง ซึ่งลืมได้)

## 3. ทางเข้ามีทางเดียว แต่แยกสามพื้นผิว

ทุกคำขอเข้า **`doPost()` (`04_auth.gs`)** แล้วแยกตาม action ไปสามพื้นผิวที่ยืนยันตัวตนไม่เหมือนกัน
(รายชื่อ action ทั้งหมดอยู่ใน [แผ่น 06 หมวด C](06-schedules.generated.md))

| พื้นผิว | ตาราง | จำนวน | ตัวตน |
|---|---|---|---|
| แอปมือถือ | `ACTION_MAP` (`05_router.gs`) | 18 | **LINE ID token** → ยืนยันกับ LINE แล้วใช้ `sub` เป็นตัวตนจริง |
| แอดมิน | `ADMIN_ACTION_MAP` (`05_router.gs`) | 190 | token จากการล็อกอิน (เก็บใน `admin_sessions`) |
| ไม่ต้องล็อกอิน | ตรวจชื่อ action ตรงๆ ใน `doPost` | 10 | ไม่มี — ล็อกอิน / สมัคร / ขอ URL ล็อกอิน LINE |

**★ `lineUserId` ที่ client ส่งมาเป็นแค่ข้อมูลประกอบ** ตัวตนจริงมาจาก ID token ที่ backend
ไปยืนยันกับ LINE เอง (`resolveLineIdentity` ใน `27_line_auth.gs`) ไม่ตรงกัน = ปฏิเสธ
→ สมัครแทนคนอื่นหรือสวมรอยไม่ได้ · ผลการยืนยันถูกแคชตามอายุ token (สูงสุด 30 นาที) จึงไม่ได้ยิง LINE ทุกคำขอ

ความเข้มขึ้นกับ env: ถ้าไม่ได้ตั้ง `ALLOW_UNVERIFIED_LINE_LOGIN` จะยอมรับคำขอที่ไม่มี token
**เฉพาะเมื่อ `ENV_NAME='uat'`** (เพื่อให้โหมดทดสอบ `?devLineUserId=` ใช้ได้) · prod เข้มเสมอ

## 4. ตัวตนกลางคือ LINE user id

กติกาเจ้าของระบบ: **ทุกบัญชีของทุกแอปผูกกับ LINE user id เสมอ**
(`admin_users.line_user_id` · `liff_users.line_user_id`) · 1 LINE = 1 บัญชีแอดมิน

- **สมัครผ่าน LINE เท่านั้น และไม่มีรหัสผ่าน** — ยืนยันตัวตนกับ LINE สำเร็จแล้วไม่ต้องตั้งรหัสซ้ำซ้อน
  · บัญชีที่ไม่มีรหัสผ่านล็อกอินด้วยรหัสผ่านไม่ได้ (`adminLogin` ตอบ `lineOnly: true`)
  · ช่อง username/password ยังมีอยู่สำหรับบัญชีเดิม ซ่อนไว้ใต้ลิงก์
- **ผู้ใช้ใหม่ทุกคนต้องเลือกสังกัดและรออนุมัติ** ได้บัญชีที่ยังไม่มีสิทธิ์อะไรเลยจนผู้ดูแลอนุมัติ
- **สายอนุมัติเป็นลำดับชั้น**: Ultra Admin อนุมัติคำขอเป็นแอดมินของตัวแทน · แอดมินบริษัทอนุมัติคำขอเข้าบริษัท
  · แอดมินของตัวแทนอนุมัติพนักงานของตัวเอง (คิวคำขอแอดมินไม่แสดงให้ฝั่งตัวแทนเลย)
- **ต้องตั้ง Callback URL ใน LINE Login channel** ให้ตรงกับที่หน้าเว็บส่ง ไม่ตรง = LINE ตอบ 400
  ตั้งแต่ขั้นแรก · LIFF app **ต้องติ๊ก scope `openid`** ไม่งั้น `getIDToken()` คืนค่าว่างและแอปวนล็อกอิน
- LINE Login channel `2010417493` · LIFF app แยกต่อ env (ดู `frontend-mobile/config.js`)

## 5. ไฟล์ฐานข้อมูลอยู่บน Drive และเจ้าของคือสคริปต์

- โครงสร้าง: `<root>/db_<env>/TNKI/` = Central Sheet + ฐานข้อมูลบริษัท ·
  `<root>/db_<env>/<รหัสตัวแทน>/` = ไฟล์ของตัวแทนรายนั้น
- `root` = Script Property `DB_ROOT_FOLDER_ID` (ค่าตั้งต้นชี้โฟลเดอร์บน Shared Drive — id ไม่เปลี่ยนตามชื่อโฟลเดอร์)
- **ไฟล์ทุกไฟล์ถูกสร้างโดย Apps Script จึงมีเจ้าของเป็นบัญชีที่รันสคริปต์** บัญชีอื่นเปิดอ่านได้แต่
  **ย้ายไฟล์ไม่ได้** → การจัดระเบียบต้องสั่งผ่าน backend (action `organizeDatabaseFiles`)
  ไม่ใช่ลากใน Drive
- งานนี้ต้องใช้ OAuth scope `.../auth/drive` (เต็ม) — `drive.file` ไม่พอ เพราะแตะได้เฉพาะไฟล์ที่แอปสร้างเอง
  แต่โฟลเดอร์ปลายทางคนสร้าง · **เปลี่ยน scope แล้วเจ้าของ deployment ต้องรัน `authorizeDriveAccess()`
  ในเอดิเตอร์หนึ่งครั้ง** เพื่อกดยอมรับสิทธิ์ใหม่ ก่อน Deploy

## 6. การขึ้นของ

| เปลี่ยนอะไร | ขึ้นอย่างไร |
|---|---|
| หน้าเว็บ (ทั้งสองแอป) | push ขึ้น `UAT` หรือ `main` → Cloudflare Pages build เอง |
| backend | `.dev/push-backend.sh uat\|prod` (เป็น `clasp push` — แค่วางโค้ดไว้ที่ HEAD) |
| **ให้ backend มีผลจริง** | **เจ้าของ deployment กด Deploy → New version ในเอดิเตอร์** |

**★ `clasp push` ไม่ทำให้ URL ที่ใช้งานอยู่เปลี่ยนโค้ด** — deployment เป็นภาพนิ่งของ HEAD ตอนกด deploy
จึงต้องกด New version ทุกครั้ง · เอดิเตอร์เองรันโค้ดที่ HEAD เสมอ (ฟังก์ชันซ่อมใน `99_dev_tools.gs`
จึงใช้ได้ทันทีหลัง push โดยไม่ต้อง deploy)

**★ ก่อนเชื่อ deployment ให้เช็คว่ามันรันโค้ดที่คิดจริง** — push จากโคลนเก่าทำให้โค้ดเก่าขึ้นไปเงียบๆ
(เกิดจริง 22 ก.ย. 2026) · เช็คเร็ว: ยิง action ใหม่แล้วดูว่ามันไม่ตอบ `ไม่พบ action`

## 7. ยังไม่ก่อสร้าง

- **ฐานข้อมูลจริง** — Sheets คือเฟส 1 โครงสร้างวางไว้รองรับการย้ายแล้ว (หน้าเว็บคุยกับ action ไม่ใช่ตาราง)
  แต่ยังไม่มีแผนเวลา · เพดานที่จะเจอก่อนคือ 6 นาทีต่อ execution ของ Apps Script
- **สภาพแวดล้อมที่สองสำหรับคนพัฒนาคนที่สอง** — ตอนนี้ UAT มีชุดเดียว เป็นคอขวดตัวจริง
  (`clasp push` เขียนทับทั้งโปรเจกต์ · Central Sheet ตัวเดียว) ดู `docs/who-is-doing-what.md`
- **`dev` ยังไม่ได้จัดไฟล์เข้าโครงสร้าง `db_dev/`**

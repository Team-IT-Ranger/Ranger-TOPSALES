### หน้าตาการ์ดของคงเหลือ

**2 คอลัมน์: `รหัส + ชื่อสินค้า` | `คลัง + รถ = รวม`** (เจ้าของระบบสั่ง 21 ต.ค. 2026 หลังทดสอบบนมือถือจริง)
- **ชื่อสินค้าตัดที่ 20 ตัวอักษร** และแถวข้อมูลใช้ตัวอักษรขนาด `xs` — รหัสอย่างเดียวจำไม่ไหวเวลาอ่านเร็วๆ
  แต่ถ้าไม่ลดขนาดตัวอักษร บรรทัดจะล้นแล้ว LINE ตัดท้ายทิ้ง (`maxLines:1`) = ตัวเลขหายจากจอโดยไม่มีอะไรฟ้อง
- ของเดิม 4 คอลัมน์ (ชื่อสินค้า · คลัง · รถ · รวม) — ชื่อสินค้ายาวกินที่จนตัวเลขเบียดกัน
- **รหัสสินค้ามาก่อน** เพราะสั้นและเป็นตัวที่คนใช้สั่งของจริง · ชื่อสินค้าไม่อยู่ในการ์ดแล้ว
- **ตัวเลขยุบเหลือช่องเดียวแต่ไม่ทิ้งข้อมูล** — เขียน `10.5 + 3 = 13.5` ซึ่งอ่านได้ในตัวเองว่าตัวไหนคืออะไร
  ไม่ต้องพึ่งหัวตาราง · ยอดรวมเป็น span สีฟ้าตัวหนา ตัวแยกเป็นสีอ่อน (ตาจับ "รวม" ได้ก่อน)
- `*` นำหน้ารหัส = ยังไม่ยืนยันขนาดบรรจุ (ตัวเลขแถวนั้นเป็นชิ้น) · แถวยอดรวมตัดบรรทัดได้เพราะยาวกว่าแถวข้อมูล
- **ท้ายการ์ดมีปุ่ม "พิมพ์รายงาน (PDF)"** → หัวข้อถัดไป

**★★ ตัวเลขหลักคือ "ของคงเหลือจริง" (on-hand) ยังไม่หักจอง**
- คลัง = `warehouse_stock.qty` · รถ = `van_stock.qty` รวมทุกคน — **ฝั่งรถไม่มียอดจอง** เพราะขายจากรถ
  ตัดสต็อกทันทีตอนบันทึกบิล ส่วนบิล "สำนักงานจัดส่ง" กันของไว้ตั้งแต่เปิดบิลแล้วตัดจริงตอน **"พร้อมจัดส่ง"**
- **แถวที่มีคนจองไว้** มีบรรทัดเล็กใต้แถว `จอง X · ขายได้ Y` · ท้ายการ์ดมียอด จอง และ **ขายได้จริง**
  — ไม่มีจอง = ไม่ขึ้นเลย ไม่รกเปล่าๆ · **สินค้าที่ไม่มีของแต่มีคนจองก็โผล่** (ขายได้ติดลบ = ต้องรีบสั่งของ)
- รายงานที่พิมพ์แยกคอลัมน์ **จอง / ขายได้** ทุกแถว (ชุดเดียวกับหน้าคลังสินค้าในแอปแอดมิน) และใช้**ชื่อสินค้าเต็ม**
- **★ ทำไมต้องมี**: กติกาของระบบคือ `ขายได้จริง = คงเหลือ − จอง` (ดู `_reservedQty`/`getAvailableQty` ใน
  `backend/34_sales_status.gs`) และคำสั่ง `สต็อก` ของบอทแสดงสามค่านี้มาตั้งแต่ต้น — ถ้าการ์ดพูดแค่ on-hand
  บอทตัวเดียวจะตอบคำว่า "ของมีเท่าไร" คนละความหมายในสองคำสั่ง

### ปุ่มพิมพ์รายงาน (`doGet`)

**★★ LINE ไม่มีชนิดข้อความแบบไฟล์เอกสารสำหรับบอท** (มีแต่ text/image/video/audio/location/imagemap/
template/flex) — บอทแนบ .pdf ส่งให้ไม่ได้ ปุ่มจึงเป็น**ลิงก์เปิดหน้าเว็บ** แล้วผู้ใช้กด "พิมพ์ → Save as PDF"

- หน้าเว็บคือ `doGet` ของโปรเจกต์นี้เอง (deployment เดียวกับ webhook) — **ไม่แตะ Drive ไม่กินโควตาข้อความ**
- **ใช้ตัวพิมพ์กลางตัวเดียวกับแอปแอดมิน**: โหลด `doc-print.js` จาก `ranger-topsales-admin.pages.dev`
  แล้วเรียก `DocPrint.table(spec)` — ได้เอกสาร A4 หน้าตาชุดเดียวกับที่พิมพ์จากแอป **ไม่เขียนตัวพิมพ์ใหม่**
  · **แก้ `doc-print.js` แล้วต้องบัมป์ `?v=` ใน `BOT_DOCPRINT_URL` ด้วย**
  · ★ เว็บแอดมินอยู่บน **Cloudflare Pages** ไม่ใช่ GitHub Pages แล้ว (github.io ตอบ 404 ให้ไฟล์)
- **รายงานเอาทุกแถว + ชื่อสินค้า + แยกคอลัมน์ คลัง/บนรถ/รวม/หน่วย** (การ์ดในแชตย่อเหลือ 15 แถวและรหัสเท่านั้น)
  · ยอดรวมสามบรรทัด: ในคลัง · บนรถ · ทั้งหมด
- **ลิงก์พก token อายุ 30 นาที** (CacheService) ผูกกับตัวแทนรายที่ขอ — เปิดได้โดยไม่ต้องล็อกอิน เพราะคนใน
  LINE ไม่มีบัญชี Google ของบริษัท · **★ ใครได้ลิงก์ในช่วงนั้นก็เปิดได้** ซึ่งเท่ากับความเปิดของการ์ดเองอยู่แล้ว
  (ในแชทกลุ่ม ทั้งกลุ่มเห็นการ์ดและปุ่ม) · ข้ามไปดูตัวแทนรายอื่นด้วย token เดิมไม่ได้
- ต่อท้าย URL ด้วย `openExternalBrowser=1` — ในเบราว์เซอร์ของแอป LINE สั่งพิมพ์/บันทึก PDF ไม่ได้
- **หน้ามีตารางธรรมดาเขียนไว้เสมอ** แล้วให้ overlay ของ DocPrint ทับ — โหลดสคริปต์ไม่สำเร็จก็ยังเห็นข้อมูล
  และสั่งพิมพ์ได้ ไม่ใช่หน้าขาวที่อธิบายไม่ได้ · ชื่อสินค้าถูก escape ทั้งใน JSON และในตาราง

## ข้อตกลงที่ต่างจาก backend หลัก (ตั้งใจ)

- **ไม่มีแนวคิดสลับ env** — อ่านข้อมูลจาก **prod เสมอ** · ลงทะเบียนผู้ใช้เขียนทั้ง prod และ uat
  (แยก try/catch ต่อไฟล์ UAT พังต้องไม่ทำให้ตอบผู้ใช้ไม่ได้) · `chatlog` เขียนลง **UAT เท่านั้น**
- **ตัวตนคือ `liff_users`** — เพิ่มเพื่อน = จองแถว `status='No'` รอแอดมินอนุมัติที่เมนู "พนักงานขาย"
  (`tenant_id` ว่างโดยตั้งใจ: คนใช้บอทเป็นฝั่งบริษัท แอดมินตัวแทนจึงไม่เห็นแถวนี้)
- **ไม่ใช้สิทธิ์รายโมดูล** — อนุมัติแล้วถามได้ทุกคำสั่ง
- `runBackfillMissingFollowers()` = ไล่ดึงรายชื่อเพื่อนบอทจาก LINE มาเติมแถวที่ขาด
  (follow event ที่หลุดไปตอน webhook ยังไม่พร้อม LINE ไม่ส่งซ้ำให้)
- Script Properties ของโปรเจกต์นี้: `CENTRAL_SHEET_FILEID_PROD` · `CENTRAL_SHEET_FILEID_UAT` ·
  `LINE_CHANNEL_ACCESS_TOKEN`

## ★ สิ่งที่ต้องรู้ก่อนรวมกับบอทในแอปหลัก (`backend/59_line_bot.gs`)

1. **★★ `'HOUSE'` เลิกใช้แล้ว กลายเป็น `'TNKI'`** (ดู CLAUDE.md หัวข้อ `OWNER_TENANT_ID`) —
   `answerSalesOrders_()` ยัง fallback เป็น `customer.tenant_id || 'HOUSE'` แล้วส่งเข้า `tenantFileId_()`
   ซึ่งหาแถว `tenant_id = 'HOUSE'` ในตาราง `tenants` ของ prod **ที่ migrate ไปเป็น TNKI แล้ว** →
   ลูกค้าที่ `tenant_id` ว่างจะได้คำตอบ "ดึงข้อมูลบิลขายไม่สำเร็จ" ทุกครั้ง · ของที่เป็น `TNKI` อยู่แล้วไม่โดน
2. **webhook ของ LINE channel หนึ่งตัวชี้ได้ URL เดียว** — บอทนี้กับบอทในแอปหลัก (`/inventory`)
   จะทำงานพร้อมกันบน channel เดียวไม่ได้ ต้องเลือกว่าใครถือ webhook หรือรวมเป็นตัวเดียว
3. **คำสั่งที่ซ้อนกัน**: `สต็อก` ของบอทนี้ = คลังกลางบริษัท หน่วยฐาน + ยอดจอง ·
   `/inventory` ของแอปหลัก = คลัง + บนรถ + รวม หน่วยลัง แยกตามตัวแทนที่ผู้ใช้ดูแล — คนละคำถาม
   แต่ผู้ใช้จะสับสนถ้ามีทั้งสองคำโดยไม่อธิบาย
4. **ตัวตนคนละตาราง**: บอทนี้ `liff_users` · แอปหลัก `admin_users` (+ สิทธิ์โมดูล `inventory`)
5. ของดีในบอทนี้ที่แอปหลักยังไม่มี: `chatlog` · ทักทายตอนเพิ่มเพื่อน + จองแถวรออนุมัติ ·
   ดึงชื่อจาก LINE · backfill ผู้ติดตาม · และ **ยอดจอง (`stock_reservations`)** ที่ `/inventory` ยังไม่หัก
